# Portfolio Tracker - Render Deployment Guide

## Prerequisites
- GitHub account
- Render account (free at https://render.com)
- Your Portfolio Tracker code pushed to GitHub

## Deployment Steps

### 1. Push Code to GitHub
```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/yourusername/portfolio-tracker.git
git push -u origin main
```

### 2. Create Render Account
1. Go to https://render.com
2. Sign up with GitHub
3. Authorize Render to access your repositories

### 3. Deploy Using Blueprint (Recommended)
1. Click **"New +"** → **"Blueprint"**
2. Connect your GitHub repository
3. Render will automatically detect `render.yaml` and create:
   - Web Service (FastAPI backend)
   - PostgreSQL database (free tier)
4. Click **"Apply"**

### 4. Set Environment Variables
After deployment, add these broker credentials in the Render dashboard:

**Zerodha:**
- `ZERODHA_API_KEY`: Your Zerodha API key
- `ZERODHA_API_SECRET`: Your Zerodha API secret
- `ZERODHA_REDIRECT_URL`: `https://your-app-name.onrender.com/api/broker/zerodha/callback`

**Angel One:**
- `ANGEL_API_KEY`: Your Angel API key
- `ANGEL_API_SECRET`: Your Angel API secret
- `ANGEL_REDIRECT_URL`: `https://your-app-name.onrender.com/api/broker/angel/callback`

**5Paisa:**
- `FIVEPAISA_API_KEY`: Your 5Paisa API key
- `FIVEPAISA_API_SECRET`: Your 5Paisa API secret
- `FIVEPAISA_REDIRECT_URL`: `https://your-app-name.onrender.com/api/broker/fivepaisa/callback`

**Auto-generated (don't modify):**
- `SECRET_KEY` - Auto-generated by Render for JWT tokens
- `ENCRYPTION_KEY` - Auto-generated for credential encryption
- `DATABASE_URL` - Auto-connected to PostgreSQL database

### 5. Frontend Deployment (Separate)

#### Option A: Deploy Frontend on Vercel (Recommended)
1. Push frontend to GitHub
2. Go to https://vercel.com
3. Import your repository
4. Set build settings:
   - Build Command: `npm run build`
   - Output Directory: `dist`
5. Add environment variable:
   - `VITE_API_URL`: `https://your-backend-name.onrender.com`

#### Option B: Serve Frontend from FastAPI
The backend already serves the frontend from `/frontend/dist` when built.
1. Build frontend locally: `cd frontend && npm run build`
2. Commit the `dist` folder (remove from `.gitignore`)
3. Backend will serve it automatically

### 6. Verify Deployment
1. Backend: `https://your-app-name.onrender.com/docs` (FastAPI docs)
2. Health check: `https://your-app-name.onrender.com/api/health`
3. Frontend: `https://your-app-name.onrender.com/` (if serving from backend)

## Database Migration (SQLite → PostgreSQL)

Your app is already configured to use PostgreSQL! The `DATABASE_URL` environment variable handles this automatically.

**No code changes needed** - Render will:
1. Create a PostgreSQL database
2. Set `DATABASE_URL` to the connection string
3. Your app will use it instead of SQLite

## Important Notes

### Free Tier Limitations
- **Sleeps after 15 minutes** of inactivity
- **Cold start**: ~30 seconds to wake up
- **750 hours/month** free (about 31 days if always on)
- **256 MB RAM**

### Performance Tips
1. **Keep it awake**: Use a service like [UptimeRobot](https://uptimerobot.com) to ping every 5 minutes
2. **Upgrade to paid**: $7/month for always-on service
3. **Database backups**: Enable in Render dashboard

### Security
- Never commit API keys to GitHub
- Use Render's environment variables for secrets
- Encryption key is auto-generated securely
- JWT secret is auto-generated

## Troubleshooting

### Build fails with "uv not found"
- The `build.sh` script installs uv automatically

### Database connection errors
- Check `DATABASE_URL` is set correctly
- Ensure PostgreSQL database is created
- Verify app has access to the database

### Cold starts too slow
- Consider upgrading to paid tier ($7/month)
- Or use a keep-alive service

### CORS errors
- Update `main.py` CORS settings to allow your frontend domain
- Example: `allow_origins=["https://your-frontend.vercel.app"]`
